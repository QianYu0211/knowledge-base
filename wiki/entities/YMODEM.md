## 定义

YMODEM 是一种运行在异步串行通信之上的**文件传输协议**，XMODEM 的重要升级版，在嵌入式固件升级（IAP/Bootloader）场景广泛使用。它引入**批处理传输**与**元数据**：一个会话可传多个文件，传输前先发包含文件名与大小的"清单"。

## 关键信息

- **XMODEM 的局限 vs YMODEM 的改进**：XMODEM 一次只能传一个文件、无元数据；YMODEM 增加批处理、文件名/大小传输、CRC-16 强校验（见 [[CRC]]）、明确的会话结束。
- **核心比喻**：XMODEM 像手推车搬家（一次一个无标签箱子）；YMODEM 像搬家公司（先发"货物清单"，再用"集装箱"运送）。
- **两种数据包**（区分唯一依据是**包序号**）：
  - **头部信息包（SEQ = 0x00）**：传输前的"货物清单"。结构 = `SOH(0x01)` + `0x00` + `0xFF(!SEQ)` + 128 字节数据 + CRC-16。数据区格式：`[文件名]\0[文件大小][空格]...\0` + 0x00 填充。
  - **文件数据包（SEQ 从 1 递增）**：`SOH(0x01)` 或 `STX(0x02)` + SEQ + !SEQ + 128/1024 字节数据 + CRC-16。末包不足时用 `0x1A`（SUB/EOF）填充。
- **为何头部包序号固定为 0**：
  1. 赋予"这是元数据包"的特殊含义，简化协议状态机；
  2. 逻辑起点清晰——元数据是"第零个包"，第一个数据块顺理成章用序号 1；
  3. **解决包序号回卷歧义**：大文件传输中序号从 `0xFF` 回卷到 `0x00` 时，靠"0 号包的元数据角色唯一且排他"区分——文件传输**过程中**的 0 号包是第 256 个数据块，文件传输**结束后**的 0 号包才是新头部信息包。
- **完整流程**（接收方 Bootloader ↔ 发送方 PC）：接收方发 `'C'` 请求 CRC 模式 → 发送方发头部包(SEQ=0) → 接收方 ACK + `'C'` → 逐个数据包 + ACK → 文件发完发 `EOT` → ACK → 下一个文件重复 → 最后发送方发**内容全 NULL 的头部包** → ACK，会话结束。
- **控制字符**：SOH(0x01 128B 包起始)、STX(0x02 1024B 包起始)、EOT(0x04 文件传输结束)、ACK(0x06 确认)、NAK(0x15 请求重传)、CAN(0x18 中止)、`'C'`(0x43 启动并请求 CRC 模式)。
- **OTA 场景**：OTA 升级用**非阻塞 Ymodem** 从服务器下载新固件，其重传/续传机制在断网或断电后可从上次位置继续，提高成功率，见 [[OTA升级]]。
- **工程实现差异**（源自《OTA面试整理》）：蓝牙 OTA 方案中 Ymodem 承担**逐帧传输 + 逐帧 [[CRC]] 校验 + 断帧重传**，保证密文完整到达外部 Flash A 区；但该具体项目**不支持断点续传**——传输中途断电仅丢弃 A 区不完整固件，下次擦除后重新传输。注意区分**断帧重传**（单帧失败即重发，协议内机制）与**断点续传**（整个会话中断后从断点继续，非 Ymodem 协议原生能力）。两套描述并存，详见 [[OTA升级]] 知识冲突。
