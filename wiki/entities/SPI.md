## 定义

SPI（Serial Peripheral Interface）是一种**同步、全双工、主从架构**的串行通信总线。它牺牲引脚数量与协议复杂度，换来极高的数据速率与简单的控制逻辑，是 MCU 与高速外设通信的主流选择。

## 关键信息

- **核心特性**：同步（独立时钟线）、主从架构（不支持多主）、全双工（可同时收发）、协议简单（无地址帧、无应答位、无仲裁）。
- **四线接口**：

  | 线名 | 别名 | 功能 |
  | --- | --- | --- |
  | SCLK | SCK | 串行时钟，由主设备产生，驱动整个传输 |
  | MOSI | SIMO, DO | 主出从入 |
  | MISO | SOMI, DI | 主入从出 |
  | CS | nCS, SS | 片选，低电平有效，多从设备中选择一个 |

- **"数据交换"本质**：主从接口可视为两个首尾相连的**环形移位寄存器**，每个 SCLK 脉冲驱动 1 位交换。由此推论——SPI **不存在纯粹的"读"或"写"，一切操作都是"交换"**：写数据时同时接收（可能无用），读数据时必须发 Dummy Byte 产生时钟。
- **速率提升（Dual / Quad SPI）**：牺牲全双工能力，数据阶段临时征用多条 I/O 线做单向并行传输。
  - **Dual SPI**：MOSI + MISO 同时作输入或输出 → 每周期 2 位，吞吐率翻倍；
  - **Quad SPI**：再征用 WP、HOLD → 四线同时传输 → 每周期 4 位，吞吐率 4 倍。
  - 工作模式：以标准 SPI 启动 → 发命令切换 → 高速传输 → 完成后切回标准模式。
- **配置核心**：CPOL/CPHA 决定时钟同步方式，主从必须一致，见 [[CPOL-CPHA]]。

### 实现方式：硬件外设 vs 软件模拟

同一套 SPI 协议有两种实现载体——**硬件外设**（MCU 内置 SPI 控制器）与**软件模拟**（GPIO bit-bang），是 [[协议分层]]"同一语言、两套扩音器"的体现（与 [[I2C]] 的硬件/软件二分同构）：

| 维度 | 硬件外设 | 软件模拟（GPIO + 延时） |
| --- | --- | --- |
| 实现载体 | MCU 内置 SPI 控制器 | 任意 GPIO + 软件延时翻转 |
| CPU 占用 | 低（写 DR 自动移位，中断/DMA 搬运） | 高（每位都要 CPU 翻转 SCLK + 采样 MISO） |
| 速率 | 精准，可达数十 Mbps（如驱动 [[W25Q64]] 高速读） | 受 CPU 主频与延时精度限制，通常慢一个量级 |
| 引脚 | 绑定特定复用引脚（Dual/Quad 需额外 I/O 线） | 任意 GPIO，布局灵活 |
| 数据交换 | 写 DR 自动移位，读自动采 MISO | 手动"置 MOSI → 拉高 SCLK → 采 MISO → 拉低 SCLK"逐位循环 |
| 配置 | 需配 CPOL/CPHA/波特率/帧格式 | CPOL/CPHA 由延时与电平代码体现，改时序即改代码 |
| 可移植性 | 依赖具体外设 | 跨 MCU 移植简单 |
| 典型场景 | 高速外设（Flash/SD/屏）、DMA 大块传输 | 低速外设、引脚受限、跨平台 |

- **硬件外设**：写数据寄存器即硬件自动移位（每周期同时发 MOSI、采 MISO），可配 DMA 让 CPU 完全不参与（如把整个 W25Q64 读块搬进内存）；Dual/Quad 模式依赖硬件多 I/O 线支持。
- **软件模拟**：核心是"**交换**"语义——读一个字节必须同时发一个 dummy 字节产生 SCLK（呼应上文"不存在纯读/写"）；每位循环 = 置 MOSI → 拉高 SCLK → 读 MISO → 拉低 SCLK；**时序期间须关中断**。
- **物理层不同（与 I2C 的关键差异）**：SPI 是**推挽输出**，无开漏、无上拉、无 ACK、无仲裁——软件模拟只需普通 GPIO 推挽即可，比模拟 I2C 简单（不需要 [[开漏输出]]/[[线与]]）。
