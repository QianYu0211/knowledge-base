## 定义

内存对齐（Memory Alignment）指**数据在内存中的存放地址要符合其类型对齐边界**的规则。CPU 通过数据总线（32/64 位）一次读取 4/8 字节，对齐的数据一次读取完成，未对齐的则需要拆分多次读取甚至触发异常。结构体因对齐规则会产生**填充（Padding）**，成员排列顺序直接影响内存占用。

## 关键信息

### 为什么需要对齐：CPU 一次读取

- CPU 通过数据总线（32/64 位）**一次读取 4/8 字节**；内存以字节为单位编址；
- **对齐的 int**（从 `0x00` 开始占 4 字节）：CPU 一次读取完成 ✅；
- **未对齐的 int**（跨越读取边界）：CPU 需要读取两次才能取完整 → 效率下降；部分架构（某些 ARM）直接产生异常。

### 对齐规则一览

| 类型 | 占用大小 | 对齐边界 |
|---|---|---|
| `char` | 1B | 1 字节（任意地址） |
| `short` | 2B | 2 字节（偶数地址） |
| `int` / `float` | 4B | 4 字节（4 的倍数地址） |
| `double` | 8B | 8 字节（8 的倍数地址） |

- **结构体规则**：成员按其类型对齐边界对齐；结构体总大小为**最大成员对齐边界的整数倍**。

### 反面教材：成员顺序不当（BadStudent）

```c
struct BadStudent
{
    char grade;   // 1B
    int  id;      // 4B
    char gender;  // 1B
};
// 预期 1+4+1=6 字节，实际 12 字节（6 数据 + 6 填充）
```

布局：`[G][P][P][P][I][I][I][I][g][P][P][P]`
- `char grade` 后 int 需 4 字节对齐 → 补 3 字节填充；
- `gender` 后为保证总大小是最大对齐（4）的整数倍 → 再补 3 字节。

### 正面教材：调整成员顺序（GoodStudent）

```c
struct GoodStudent
{
    int  id;      // 4B
    char grade;   // 1B
    char gender;  // 1B
};
// 实际 8 字节，节省 4 字节（33%）
```

布局：`[I][I][I][I][G][g][P][P]`
- **把大的成员放前面、小的成员聚在一起**，只留 2 字节尾部填充。

### 补充知识

- **`#pragma pack(n)`**：修改对齐方式，`#pragma pack(1)` 强制紧凑排列（省空间但可能牺牲访问效率），**嵌入式跨通信协议**（结构体直接映射报文）时常用；
- **指针大小**：32 位平台 4 字节、64 位平台 8 字节，对齐边界相应 4/8；
- **对齐的意义**：对齐访问一次完成，未对齐访问需拆分多次；部分架构直接异常。

### 关键结论

1. CPU 一次读取 4/8 字节，对齐数据一次完成、未对齐需两次；
2. 结构体内存 = 数据 + 填充（Padding），总大小按最大成员对齐；
3. 优化技巧：**大的成员放前面、小的成员聚在一起**，可显著省内存（BadStudent 12B → GoodStudent 8B，省 33%）。
