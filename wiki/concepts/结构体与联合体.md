## 定义

结构体（`struct`）与联合体（`union`）是 C 语言两种**自定义复合数据类型**。核心区别在存储方式：**结构体给每个成员分配独立内存**，同一时刻所有成员都有效；**联合体让所有成员共享同一块内存**，同一时刻只有最后写入的成员有效，写一个会覆盖其他。

> 一句话记忆：**struct 是"多个抽屉各自装东西"，union 是"一个抽屉换着装不同东西"**——同时保存多种信息用 struct，在同一块内存上做不同解读/省内存用 union。

## 关键信息

### 核心区别对比

| 维度 | 结构体 `struct` | 联合体 `union` |
| --- | --- | --- |
| 存储方式 | 每个成员**独立**内存 | 所有成员**共享**同一块内存 |
| 内存大小 | 所有成员之和 + 对齐填充 | **最大成员**的大小（按对齐） |
| 同时有效性 | 所有成员同时有效 | 仅最后写入的成员有效 |
| 写入行为 | 各写各的，互不影响 | 写一个成员会覆盖其他成员 |
| 典型用途 | 组合不同类型为一个"记录" | 省内存 / 数据多重视角 / 协议解析 |
| 赋值语义 | 整个记录整体拷贝 | 位级覆盖 |

### 内存大小差异（32 位示例）

```c
struct S {          // 结构体：所有成员相加 + 对齐填充
    char  c;        // 1 字节
    int   i;        // 4 字节（c 后填充 3 字节）
    short s;        // 2 字节（尾部填充 2 字节）
};                  // sizeof = 12 字节

union U {           // 联合体：取最大成员
    char  c;        // 1
    int   i;        // 4
    short s;        // 2
};                  // sizeof = 4 字节
```

结构体大小受**对齐规则**支配，成员顺序影响填充量与总大小——见 [[内存对齐]]：

> 结构体规则：成员按其类型对齐边界对齐；结构体总大小为**最大成员对齐边界的整数倍**。

这正是结构体"1+4+2 ≠ 7 而是 12"的原因。

### 嵌入式经典用法：union 做"数据视图"

**同一块内存，用不同类型去解读**——union 在嵌入式中最有威力的用法，常见于协议/寄存器解析：

```c
union {
    uint8_t  bytes[4];          // 原始字节视角
    uint32_t word;              // 整体数值视角
    struct {                    // 拆分字段视角
        uint8_t b0, b1, b2, b3;
    } parts;
} reg;
```

- 底层 DMA/硬件写入 `reg.bytes`，应用层读 `reg.word` 或 `reg.parts.b1`，**零拷贝解析**；
- 这是协议报文解析（如 [[BLE广播]] 的 AD Structure、串口/CAN 帧）的底层手法——把字节流重叠成字段结构；
- 协议映射常配合 `#pragma pack(1)` 消除填充（见 [[内存对齐]]）。

### 主要陷阱

1. **未激活成员访问**：读一个"不是最后写入"的成员，C++ 属未定义行为；C 里按位解释（工程上常用但需自行负责语义）；
2. **大小端（字节序）**：`bytes[0]` 在大小端机器上对应 `word` 的低字节或高字节**不同**——跨平台/跨协议必须显式处理；
3. **严格别名规则**：union 类型双关在 C 严格别名规则下属灰色地带，嵌入式编译器通常允许，高性能/可移植代码需注意；
4. **含指针成员**：结构体/联合体的拷贝都是位拷贝，涉及 [[深拷贝与浅拷贝]] 的共享陷阱——浅拷贝会共享指针指向的数据。
