## 定义

看门狗（Watchdog）是一种"**喂狗证明存活**"的可靠性机制：被监护对象必须在规定时间内刷新"我还活着"的信号（喂狗），否则判定故障并触发恢复。按实现分两类：

- **硬件看门狗**：独立定时器，失喂即**强制复位**系统——最可靠、粒度最粗（整个系统级）；
- **软件看门狗**：看门狗线程监控各业务线程，失喂即**上报错误线程做软恢复**——可编程、粒度细（线程级）。

两类可**分级组合**：软件看门狗负责线程级监护，硬件看门狗兜底软件看门狗本身，构成"分层监护"。

## 核心思想：喂狗 = 存活证明

把"系统/线程还活着"的证明交给一个不断倒计时的计时器或监控者——健康程序周期性喂狗证明自身存活；一旦失喂即视为故障，触发复位或恢复。看门狗的价值在于：**把故障检测从"人肉排查"变成"自动倒计时"**。

## 硬件看门狗：定时器兜底

- **物理特性**：独立于 CPU 运行的硬件定时器，启动后不可关闭，基于独立时钟源（如 IWDG 用 LSI），不受软件跑飞影响。
- **OTA 应用**：[[Bootloader]] 在跳转新 App 前开启看门狗（参考工程 **4 秒**），新 App 必须在窗口内正常执行到程序末端并写入"正常运行"标志位；若超时未更新，看门狗强制复位回 BootLoader，BootLoader 判定新固件有问题并**回滚 B 区备份**，防止变砖。
- **源码级实现**：`BootManager_JumpToApp()` 命中 `g_JumpInit` 时调用 `IWDG_Init(IWDG_Prescaler_64, 3000)`——64 分频 + 重载值 3000，基于 LSI 约数秒级窗口（见 [[Bootloader]]）。
- **与 [[启动流程]] 的关系**：看门狗复位使系统重新走上电自检路径，[[Bootloader]] 据此判读标志位决定「跳转 / 回滚 / 等待升级」。

## 看门狗线程架构：软件看门狗分级监护

采用"**一个看门狗线程监控所有线程 + 一个硬件看门狗兜底看门狗线程**"的分层架构（素材：`assets/看门狗线程框图.png`）：

![[看门狗线程框图.png]]

### 三级职责链

```
硬件看门狗（最后防线：只看门狗线程本身）
   ↑ 喂狗
看门狗线程（软件看门狗：监控所有线程）
   ↑ 注册 / 喂狗 / 超时上报
业务线程（线程 A、AHT21…）
```

### 关键机制

- **注册**：每个线程启动时向看门狗线程**注册自己的看门狗**；看门狗线程按注册时间计算该线程的超时窗口。
- **喂狗 = 实时性证明**：线程须在规定时间内**遍历一遍自己的程序**（会自行阻塞的任务除外），每轮遍历向看门狗线程发一个"下一个消息通知"（喂狗）；超时未收到 → 判定**异常阻塞（不满足实时性）**。
- **恢复**：看门狗线程把错误信息发给**错误线程**，由错误线程**尝试重启异常线程**。
- **硬件看门狗职责**：只负责看门狗线程本身——看门狗线程若也卡死，硬件看门狗强制复位系统。因此**整个系统只需一个硬件看门狗**。

### 案例：AHT21 温湿度传感器线程

在执行外部传入的 API 回调函数时**执行前注册看门狗**；若回调长时间未执行完，看门狗收不到喂狗信号，即判定被传入的 API 有问题，于是看门狗发错误给错误线程，错误线程尝试重启 AHT21 线程。

### 设计价值

- 软件看门狗可编程、能区分故障类型 → 精确到"哪个线程、哪个回调"出错，做**软恢复**（重启线程而非复位整个系统）；
- 硬件看门狗只兜底看门狗线程本身 → 单点喂狗升级为**分层监护**，故障隔离粒度更细；
- 一个硬件看门狗 + 一个软件看门狗线程，即可监护任意数量的业务线程。
