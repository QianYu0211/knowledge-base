## 定义

Modbus 报文结构定义"信息 → 数据"转换后的**二进制帧格式**：一帧由**从站地址 + 功能码 + 数据段 + 校验码**四段组成。功能码标识"做什么操作"（读哪个寄存器、写几个等），数据段承载"操作对象与内容"，是 Modbus 协议最核心的编码规则。

## 关键信息

### RTU 报文四段格式

| 字段 | 长度 | 说明 |
|---|---|---|
| **从站地址** | 1 字节 | 从站身份 ID，范围 **1~247**，故一网最多 247 个从站；0 为广播地址 |
| **功能码** | 1 字节 | 各操作的编号（读/写、线圈/寄存器、单个/多个） |
| **数据段** | N 字节 | 起始地址（16 位，高八位在前）+ 数量/内容，长度随功能码变化 |
| **校验码** | 2 字节 | **CRC-16**，检测传输错误 |

- **多字节字段字节序**：16 位地址/数量/值均**高八位放高位、低八位放低位**（大端序）。
- **帧结构演进**：串口以字节为单元，协议把 16 位"字"拆成高字节+低字节再传输，以满足底层按字节收发。

### 常用功能码（操作编号）

| 功能码 | 操作 | 对象 |
|---|---|---|
| 0x01 | 读线圈 | 线圈寄存器（bit） |
| 0x02 | 读离散输入 | 离散输入寄存器（bit） |
| 0x03 | 读保持寄存器 | 保持寄存器（word） |
| 0x04 | 读输入寄存器 | 输入寄存器（word） |
| 0x05 | 写单个线圈 | 线圈（bit，写 1=`0xFF00`，写 0=`0x0000`） |
| 0x06 | 写单个保持寄存器 | 保持寄存器（word） |
| 0x0F | 写多个线圈 | 线圈（bit 批量） |
| 0x10 | 写多个保持寄存器 | 保持寄存器（word 批量） |

### 请求/响应交互流程

1. **主站组帧**：填入从站地址、功能码、起始地址（高八位→低八位）、数量/写入值，计算 CRC 附加在帧尾后发送。
2. **物理层广播**：RTU 基于串口，物理层上所有从站都能收到请求（广播特性）。
3. **从站过滤**：各从站对比首字节从站地址——地址不属于自己则**丢弃**；地址匹配则继续。
4. **CRC 校验**：用接收数据重算 CRC，与帧尾 CRC 比对，一致才接收处理（先校验后处理，避免白做）。
5. **从站响应**：按请求操作寄存器，构造响应报文返回主站；读操作需在响应中给出数据（含高位补零规则：如 3 个 bit 不足 1 字节时高 5 位补 0，并在字节数字段填实际字节数），写操作常回显请求报文（写多个时去掉字节数与数据字段、重算 CRC）。
6. **主站确认**：收到响应后对比从站地址、CRC，并将响应与原请求报文比对（常比前六字节），确认是目标从站的响应。

### 设计要点

- **先校验后处理**：从站先做地址过滤与 CRC 校验，全部通过才解析处理，防止被错误/干扰数据触发误操作。
- **最小响应粒度**：即使只读 3 个 bit，发送报文最低也是 1 字节，故不足字节的位数据需高位补零。
- **写多响应简化**：写多个寄存器/线圈的响应去掉数据字段、重算 CRC，比请求报文更短。
