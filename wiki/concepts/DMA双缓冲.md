## 定义

双缓冲（Double Buffering）开辟两块内存 A/B 交给 DMA 调度：DMA 填满 A 后切换目标到 B 继续搬运，同时 CPU 处理 A；A 处理完、B 填满后再互换。DMA 与 CPU 各用一块、互不等待，构成"生产-消费"流水线。

## 关键信息

- **原理**：DMA 搬运数据到 A → 中断更新信号量 → 处理 task 处理 A、调度 task 把目标切到 B 重启转换 → 分叉（先处理完 / 先转换完）→ 闭环循环。
- **同步机制**：用"空内存数量 / 满内存数量"两个计数 [[信号量]] 协调。满内存 > 0 才让处理 task 干活；空内存为 0 时调度 task 阻塞等待。
- **分叉说明**：
  - 先处理完 → 信号量恢复，目标地址切回刚释放的块，闭环；
  - 先转换完 → 两块都满、空内存为 0，调度 task 阻塞，等处理完释放。
- **隐式 vs 显式**（串口场景）：
  - 隐式双 Buffer：一块连续地址 + 半满中断，硬件自动乒乓，ISR 只通知、不切换。
  - 显式双 Buffer：两块独立内存，ISR 显式切换 DMA 目标地址，控制力强但需维护两缓冲状态。
- **2×2 架构矩阵**：双 Buffer（隐式/显式）与解包方式（原地/异地）组合成四种串口架构，见 [[解包策略]]。
- **OTA 下载场景**：`中断 + DMA + AB 双缓冲` 是 OTA 固件下载的"黄金组合"——DMA 存满 A 后中断切到 B 无缝续收，CPU 把 A 的地址经 [[消息队列]] 交给 Flash 线程，见 [[OTA升级]]。
