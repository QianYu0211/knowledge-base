## 定义

系统跟踪工具是嵌入式开发中用于"**看清系统运行时行为**"的手段，按原理分三类：**软件插桩（SystemView）、硬件追踪（ETM Trace）、软件日志（时间戳日志）**。它们的共同目标是回答"系统到底在干什么、时间花在哪"，是 [[综合-降低cpu占用率]] 与 [[中断优化]] "先量化再优化"原则的前提。

> 一句话：**SystemView 看逻辑事件、ETM 看指令流、软件日志看自定义记录**——三者在"能看什么、侵入性、成本"上互补。

## 关键信息

### 三种手段对比

| 维度 | SystemView（软件插桩） | ETM Trace（硬件追踪） | 软件日志 |
| --- | --- | --- | --- |
| **原理** | RTOS 事件钩子记录 | ARM 内嵌 Trace 硬件 | ISR/任务打时间戳入日志 |
| **看到什么** | 任务/中断/队列/信号量等**逻辑事件** | **每条指令**的执行流与精确时序 | 自定义打印/时间戳 |
| **侵入性** | 低（记录函数 + [[环形缓冲区]]） | **无侵入**（纯硬件） | 有（代码插桩 + 传输开销） |
| **依赖** | RTOS 支持 + J-Link/UART | ARM Trace 硬件 + Trace 调试器 | 定时器 + 日志通道 |
| **典型场景** | RTOS 调度/阻塞/优先级分析 | 精确时序、崩溃定位 | 业务逻辑追踪、现场日志 |
| **成本** | 中（工具 + 移植） | 高（硬件支持） | 低 |

### 选型建议

| 场景 | 选谁 |
| --- | --- |
| 分析 RTOS 任务调度、阻塞、优先级反转 | **SystemView** |
| 精确到指令/微秒级的时序定位、崩溃分析 | **ETM Trace** |
| 长期运行、现场问题、自定义业务事件 | **软件日志**（时间戳入 [[环形缓冲区]]） |
| 资源紧张、无 Trace 硬件 | 软件日志（最廉价的起点） |
| 先定位"哪里慢"再深入 | 软件日志/SystemView 粗筛 → ETM 精查 |

### 一句话记忆

> **SystemView 看逻辑（软件插桩）、ETM 看指令（硬件追踪）、软件日志看自定义（成本最低）**——先日志粗筛、再 SystemView 看调度、最后 ETM 精确定位。
