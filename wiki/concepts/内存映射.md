## 定义

内存映射（Memory Mapping）是"**把某种东西安排到地址空间的特定位置**"——建立"名称 → 地址"的对应关系。在嵌入式里最常见的有四种：**程序段映射、外设寄存器映射、硬件自举映射、MMU 虚拟内存映射**。核心是前两种。

> 一句话：**内存映射 = 给"代码段 / 外设寄存器 / 虚拟地址"安排住处**。嵌入式最核心的是"链接脚本定地址（LMA/VMA）+ 启动代码搬家 + 寄存器即地址"三件事。

## 关键信息

### 四种语境（先分清在说哪个）

| 语境 | 映射什么 → 到哪 | 代表 |
| --- | --- | --- |
| **① 程序段映射** | 编译出的 `.text/.data/.bss` 段 → Flash/RAM 具体地址 | [[启动流程]] LMA/VMA |
| **② 外设寄存器映射** | 外设寄存器 → 地址空间特定区间（MMIO） | [[STM32]] 操作寄存器 |
| **③ 硬件自举映射** | BOOT 引脚决定 Flash/SRAM/系统存储器 → `0x00000000` | [[启动流程]] 阶段① |
| **④ MMU 虚拟内存映射** | 虚拟地址 → 物理地址（页表） | [[综合-rtos与linux]] |

### 核心：程序段映射原理（LMA / VMA）

编译链接时，程序被切成段，**链接脚本（`.ld`/`.sct`）就是"内存建筑蓝图"**（[[启动流程]] 阶段③）：

> 已初始化变量 `.data` 定义**双地址**：**LMA**（加载地址，Flash 中的初值仓库）与 **VMA**（运行地址，RAM 中的读写新家）；未初始化 `.bss` 只在 RAM 预留空地。

```
Flash（加载侧 · LMA）               RAM（运行侧 · VMA）
┌────────────────────┐           ┌────────────────────┐
│ .text   代码        │           │ .data   已初始化变量 │ ← 上电后从 LMA memcpy 搬来
│ .rodata 常量        │           │ .bss    未初始化变量 │ ← memset 清零
│ .data   初值仓库 ────┼── memcpy ─→ │ 堆 + 栈             │
└────────────────────┘           └────────────────────┘
```

**为什么要有双地址**：Flash 掉电不丢（存初值），但变量要**能改**，必须住在 RAM——所以 `.data` 的"**家**"（VMA，RAM）和"**仓库**"（LMA，Flash）是两处。上电后由 C 库 `__main` 按蓝图"施工"（[[启动流程]] 阶段⑤）：

> 从 LMA **memcpy 搬运 `.data`** 到 VMA、**memset 清零 `.bss`**，然后调用 `main()`。

这就是"程序被映射进内存"的完整原理：**链接脚本定地址，启动代码搬家，变量从此住在 RAM 运行**。

### 外设寄存器映射（MMIO）

MCU 的外设寄存器也被"映射"到地址空间——**操作外设 = 读写特定地址**：

```c
// STM32 GPIOA 的寄存器被映射到 0x40020000 区间
GPIOA->ODR = 0x1;   // 写这个"地址" = 控制引脚输出
```

无需 `in/out` 指令（x86 才有），ARM 用统一地址空间，**CPU 看到的所有东西（内存、外设、Flash）都是地址**——这正是 [[野指针与内存安全]] 里"写寄存器地址会触发硬件异常"的物理基础。

### 进阶：MMU 虚拟内存映射

有 MMU 的系统（[[综合-rtos与linux]] 的 Cortex-A/Linux）再做一层：程序看到的是**虚拟地址**，MMU 经**页表**翻译成**物理地址**，用 TLB 缓存加速。这层映射带来**进程隔离**（每个进程独立虚拟空间）——这是"MCU 无 MMU、Linux 有 MMU"的本质差异，也是为什么野指针在 Linux 上触发段错误、在 MCU 上直接写坏内存。

### 一句话记忆

> **内存映射 = 给"代码段 / 外设寄存器 / 虚拟地址"安排住处**。嵌入式最核心的是"链接脚本定地址（LMA/VMA）+ 启动代码搬家 + 寄存器即地址"三件事。
