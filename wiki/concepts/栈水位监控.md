## 定义

栈水位监控（Stack High Water Mark）是 FreeRTOS 提供的**任务栈余量检测**机制：系统在运行时追踪每个任务栈的**历史最低剩余量**，开发者通过 API 查询这个"水位"，判断任务栈是否分配过小（可能溢出）、过大（浪费 RAM），从而定量指导栈大小配置。

## 关键信息

### 前置配置（FreeRTOSConfig.h）

必须重新定义以下 3 个宏，否则相关 API 不可用：

```c
#define configUSE_TRACE_FACILITY                1
#define configUSE_STATS_FORMATTING_FUNCTIONS    1
#define INCLUDE_uxTaskGetStackHighWaterMark     1
```

### 核心 API

| API | 作用 | 返回值单位 |
|---|---|---|
| `uxTaskGetStackHighWaterMark(TaskHandle_t xTask)` | 查询指定任务**历史剩余最小栈内存**（栈水位） | **字**（×4 得字节） |
| `vTaskList(char *pcWriteBuffer)` | 生成所有任务信息表（Name/State/Priority/Stack/Num） | **字节**（表格文本） |

### 典型用法（打印任务内轮询）

```c
static void showTaskInformation(void *args)
{
    char pcWriteBuffer[200] = {0};
    for (int i = 0; i < 10; i++) {
        vTaskList(pcWriteBuffer);                       // 全任务信息表
        LOG("%s\r\n", pcWriteBuffer);
        val = uxTaskGetStackHighWaterMark(taskHandleA);
        LOG("Minimum historical remaining memory: %d bytes\r\n", (int)val * 4);  // 字×4=字节
        vTaskDelay(1000);
    }
    vTaskDelete(NULL);
}
```

### 判断方法

- **水位偏低**（接近 0）：任务栈接近耗尽，存在栈溢出风险 → 调大 `xTaskCreate()` 的栈大小参数；
- **水位很高**（远大于实际使用）：栈分配过大、浪费 RAM → 可适度调小；
- 通过**长时间运行 + 压力场景**观察历史最低水位，能得到任务栈的真实峰值需求，是"分配多少栈"的**实证依据**。

### 设计要点

- 返回值**单位是"字"（word）**，乘以 4（32 位 MCU）才是字节数——这是最常见的误用点。
- 栈水位是**历史最低余量**（即曾经最接近溢出的程度），不是当前值；配合 [[任务栈大小估算]] 的三个因素可精确配置。
- 任务栈是任务切换时保存寄存器上下文的场所，栈不足会破坏 [[任务上下文切换]]，导致不可预期的崩溃。
