## 定义

中断优化是一套以**"急诊室"比喻**贯穿的方法论：中断系统是急诊室、外部事件是救护车抵达、CPU 是唯一值班医生、ISR 是初步诊断、RTOS 任务是对应病房的常规治疗。目标是在各种突发情况下做到**响应最快、处理最高效、不出任何差错**，它统领三个子问题：[[中断优先级]]（分级制度）、[[中断上半部与下半部]]（急诊与病房的分工）、[[优先级反转]]（交接中的事故）。

## 中断延时：实时性的生命线

### 什么是中断延时

中断延时（Interrupt Latency）是从"中断事件发生"到"ISR 第一条指令开始执行"的时间差。它是实时系统的生命线指标——决定了系统对紧急事件的响应速度，直接关系 [[综合-优先级规划]] 的 deadline 能否守住。

### 构成：硬件底 + 软件拖长

```
中断事件发生 ──[硬件仲裁]──[自动压栈 12周期]──[取向量]──> ISR 第一条指令
              └────────── 中断延时（物理下限 ~120ns @100MHz）───────────┘
                                                          ↑ 若被更高优先级中断抢占：还要等它跑完
                                                          ↑ 若正处于关中断临界区：还要等临界区结束
```

- **硬件固有部分**（~120ns 物理下限 @100MHz）：硬件仲裁 + Cortex-M4 自动压栈 **12 时钟周期** + 取向量——**不可压缩**；
- **软件拖长部分**（才是问题）：关中断临界区过长、更高优先级中断反复抢占——**可优化**。

### 延时长了的后果（逐级恶化）

| 后果 | 表现 |
| --- | --- |
| **错过 deadline** | 该 20μs 内处理的采样拖到 100μs → 控制环路失效 |
| **丢中断** | 事件在延时期间被新事件覆盖 → FIFO 溢出 / 寄存器被覆盖 |
| **数据陈旧** | 时间敏感数据没及时读走 → 系统用过期值 |
| **协议超时** | CAN/串口处理延迟超协议窗口 → 违反协议 |
| **实时性雪崩** | 一个中断被拖长 → 高优中断排队 → 响应全面失效 |

### 如何压短

- 合理 [[中断优先级]] 嵌套、**最小化关中断段**（`__disable_irq(); g_counter++; __enable_irq();`）；
- 延迟苛刻的 ISR 放 SRAM/TCM（`.ramfunc` 段）实现 0 等待取指；
- ISR 只做必要操作，重活移交下半部（见下文"优化手段"）。

## 中断跟踪：先量化再优化

优化前先测准延时与耗时，三种手段：

- **GPIO 翻转法**：ISR 入口拉高/出口拉低某引脚，示波器测脉冲宽得执行耗时、测上升沿得中断延迟；
- **ETM Trace**：ARM 内置硬件追踪 + Trace 调试器，无侵入实时捕获完整执行流（如 Segger Ozone 显示 `main_loop` 被 `TIM2_IRQHandler` 中断 5.2μs、又被 `CAN_RX_IRQHandler` 抢占 1.5μs）；
- **软件日志**：ISR 出入口读高精度定时器，把时间戳 + 中断 ID 打入 [[环形缓冲区]]，由低优先级任务打印。

## 丢中断：四种"医疗事故"

延时过长/处理不当的极端后果——丢中断：

1. **连清标志位**：软件清标志覆盖硬件几乎同时的置位（读 DR 后执行 `SR=0` 误清新到达字节的 RXNE）；
2. **悬起脉冲**：毛刺/未清标志导致中断风暴（机械按键抖动触发 5-10 次 GPIO 中断）；
3. **未清标志位**：ISR 忘清标志 → 立即重复进入 → 系统卡死在该中断；
4. **总线仲裁冲突**：DMA 占用 AHB 总线延迟 CPU 取指 → CAN FIFO 溢出丢帧。

## 优化手段：三面

- **缩短延迟**：见上文"如何压短"（优先级嵌套、最小关中断、`.ramfunc`）；
- **精简上半部**：ISR 去除函数调用/复杂分支/循环/浮点/printf，只做时间敏感、硬件敏感、不可重入的必要操作；
- **优化下半部**：中断线程化用 [[消息队列]] 唤醒任务、无 RTOS 用主循环轮询回调（射线回调）、确保下半部任务优先级"近高"。

## 配套原则

- ISR 绝不等待任务持有的锁（见 [[优先级反转]]）；
- 中断共享变量规范见 [[volatile]]。
