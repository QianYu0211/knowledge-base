# 怎样实现高效的 ADC 采集

## 核心结论

高效的 ADC 采集本质上是一条**让 CPU 逐步退出的优化路径**：从"CPU 亲自守着转换"到"CPU 只发号施令"。核心原则是——**CPU 只负责发起，转换交给 ADC、搬运交给 DMA，CPU 在整个任务结束后才被占用一次**（见 [[摘要-adc-dma]]）。

完整配方分三个层次：

```
转换模式配置（扫描/连续/非连续，按需组合）
        ↓
取数方式升级（轮询 → 中断 → DMA）
        ↓
双缓冲 + 信号量（生产-消费流水线，并发+并行）
```

## 第一层：选对转换模式

[[ADC转换模式]] 的三个开关决定"一次触发转换多少通道、转换完干什么"，按场景组合：

| 场景 | 推荐组合 | 理由 |
| --- | --- | --- |
| 单一传感器简单读取 | Scan 关闭 | 每次触发只转一个通道，简单高效 |
| 多传感器持续监测 | 扫描 + 连续 | 按通道序列循环转换全部通道，数据寄存器持续刷新 |
| 控制周期内分批采样 | 扫描 + 非连续 | 把序列分成小组（1~8 通道/组），每次触发只转一组，降低单次 CPU 负担 |

例：6 通道、非连续数目 2 → 分 3 组，需 3 次触发完成全部通道，适合实时控制系统中"每个控制周期只采样部分通道"。

## 第二层：升级取数方式

结合 [[ADC]] 中的描述，CPU 介入有三种境界：

1. **轮询等待**——CPU 被转换过程占用，原地等待，效率最低；
2. **转换完成中断**——CPU 只在每次转换完成后被短暂占用；
3. **ADC + DMA**——ADC 转完数据，[[DMA]]（总线上的独立 Master）自动把结果搬进内存，搬运完成后才由 DMA 发一次中断。CPU 全程只被占用一次。

境界 3 是高效采集的标配：**ADC 负责"生产"，DMA 负责"搬运"，CPU 负责"消费"**。

## 第三层：双缓冲流水线

这是效率的关键跃升。[[DMA双缓冲]] 开辟两块内存 A/B：

- DMA 填满 A → 目标地址切到 B 继续填，同时 CPU 处理 A；
- 用"空内存/满内存"两个计数 [[信号量]] 协调节奏：满内存 > 0 才让处理任务干活，空内存 = 0 时调度任务阻塞等待；
- 谁也不用等谁，形成**生产-消费流水线**。

其底层原理是 [[并发与并行]] 的叠加：

> DMA 与 CPU 在**硬件上并行**（DMA 是独立 Master，填 B 的同时 CPU 处理 A）；CPU 内部用中断 + 信号量做**软件并发**（单核上任务交错推进）。只要处理速度跟得上转换速度，CPU 就永远不用等 DMA。
