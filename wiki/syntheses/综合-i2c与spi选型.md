# 综合：I2C 与 SPI 选型

**一句话总览**：**I2C 是"少引脚、多设备、有确认、但慢"的协商式总线；SPI 是"多引脚、高速、全双工、但无确认"的点对点总线。** 二者是 [[协议分层]] 下对"速度 / 引脚 / 复杂度 / 可靠性"的不同取舍——**选谁取决于你的外设是"少量配置数据"还是"大块高速数据"**。

## 核心对比总表

| 维度 | [[I2C]] | [[SPI]] |
| --- | --- | --- |
| 引脚数 | **2**（SCL/SDA） | 4 + 每从机 1 CS |
| 速率 | 100k ~ 3.4M（标准/快速/快+/高速） | 数十 Mbps（时钟多快传多快） |
| 双工 | 半双工（单根 SDA） | **全双工**（MOSI/MISO 独立） |
| 多设备 | **地址寻址**（不占引脚） | CS 片选（每从机占 1 引脚） |
| 多主 | **支持**（线与仲裁） | 标准不支持 |
| 确认 | **有 ACK**（第 9 周期） | 无 |
| 协议复杂度 | 高（地址/ACK/START/仲裁/时钟拉伸） | **低**（无协议开销） |
| 物理层 | [[开漏输出]] + 上拉（[[综合-i2c开漏物理层]]） | 推挽（[[开漏与推挽]]） |
| 软件模拟难度 | 难（时序+ACK+仲裁） | 易 |
| 典型外设 | 传感器、EEPROM、RTC、PMIC | Flash、SD 卡、显示屏、ADC/DAC |

## I2C 优缺点（[[I2C]]）

**优点**：
- **引脚极少**：仅 SCL + SDA 两线，适合引脚紧张的 MCU；
- **多设备易扩展**：靠**地址寻址**，一根总线挂多从机，从机数不占引脚；
- **有 ACK 应答**：第 9 周期从设备拉低 SDA 确认收到，主设备可知"是否送达"（[[线与]] → ACK）；
- **支持多主仲裁**：多个主设备可安全竞争总线（价低者得，[[综合-i2c开漏物理层]]）；
- **天然电平转换**：开漏上拉到目标电压域，3.3V 主控可挂 5V 从机（[[开漏与推挽]]）。

**缺点**：
- **速率低**：比 SPI 慢一个量级——开漏上升沿靠电阻充放电；
- **协议复杂**：地址、ACK、START/STOP、仲裁、时钟拉伸，软件实现与调试成本高；
- **可靠性坑多**：不同从机时钟拉伸/时序兼容性不一，部分硬件外设实现有 bug；
- **半双工**：单根 SDA 数据线，同一时刻只能收或发。

## SPI 优缺点（[[SPI]]）

**优点**：
- **速率极高**：无协议开销，可达数十 Mbps，可 Dual/Quad 再翻倍；
- **全双工**：MOSI/MISO 同时收发；
- **协议极简**：无地址、无 ACK、无仲裁，实现与软件模拟都很简单；
- **驱动强**：推挽输出，速度快、驱动能力强（[[开漏与推挽]]）；
- **CS 片选明确**：无地址冲突风险，从机被选中才响应。

**缺点**：
- **引脚多**：4 线起步，每加一个从机多一根 CS，从机多时引脚爆炸；
- **无 ACK**：从机收没收到无法确认，可靠性需上层保障；
- **不支持多主**：标准 SPI 单主，多主需外部仲裁；
- **从机不能主动发言**：只能等主设备 CS 选中 + 发时钟；
- **读必须发 dummy**：外设如 Flash 读数据也要主设备产生时钟（"交换"本质）。

## 选型决策树

```
外设要传什么数据？
  │
  ├── 大块/高速数据（Flash、SD、屏刷新、ADC高速采集）
  │       → SPI（吞吐优先；Dual/Quad 更佳）
  │
  └── 少量/低速数据（传感器寄存器、EEPROM、RTC、PMIC 配置）
          │
          ├── 从机数量多 / 引脚紧张？
          │     → I2C（地址寻址不占引脚）
          │
          ├── 需要"确认从机收到了"？
          │     → I2C（有 ACK）
          │
          ├── 需要同时收发？
          │     → SPI（全双工）
          │
          └── 需要最高速率？
                → SPI
```

| 场景 | 选谁 | 理由 |
| --- | --- | --- |
| 少量配置寄存器、多从机、引脚紧张 | **I2C** | 两线 + 地址，省引脚 |
| 大块高速数据（Flash/SD/屏） | **SPI** | 高吞吐 + 简单协议 |
| 需要确认"从机收到了" | **I2C** | 有 ACK |
| 需要同时收发 | **SPI** | 全双工 |
| 从机数量多且都是低速 | **I2C** | CS 会占太多引脚 |
| 需要最高速率（如显示刷新） | **SPI**（Dual/Quad 更佳） | 速率碾压 |

## 三个深一层认知

1. **"多设备"的成本不同**：I2C 用**地址**换引脚（不占线），SPI 用**CS 线**换简单（每从一根）——从机越多，SPI 的引脚劣势越明显；
2. **"可靠性"的来源不同**：I2C 把 ACK 做进**物理层**（开漏 + 线与），SPI 的可靠性只能靠**上层协议**（如帧头 + CRC，见 [[综合-可靠传输工具箱]]）；
3. **软件模拟的难度不同**：SPI 推挽 + 无协议 → 模拟容易；I2C 开漏 + ACK + 仲裁 → 模拟难且必须关中断保时序（[[I2C]] 实现层）。

> **一句话记忆**：**I2C = 省引脚、多设备、有确认、慢；SPI = 快、简单、全双工、但费引脚、无确认**。低速配置选 I2C，高速数据选 SPI。
