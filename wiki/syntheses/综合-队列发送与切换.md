# 综合：队列发送后，唤醒高优先级任务会立即切换吗？

**一句话总览**：**"唤醒"和"切换"是两回事**——发送队列总会**唤醒**等待者（移入就绪列表）；但**是否立即切换**取决于两个条件——**① 唤醒的任务优先级是否更高；② 发送发生在任务上下文还是 ISR 上下文**。**任务上下文发送 → 立即切（PendSV）；ISR 中发送 → 不立即切，退出中断时才经 PendSV 切。**

## 先厘清"唤醒"这一步

发送队列时的内核动作（[[消息队列]] 的等待列表）：

```
xQueueSend（入队）
   ├── ① 拷贝消息进槽位
   └── ② 若 xTasksWaitingToReceive 非空：
         移出最高优先级等待者 → 移入就绪列表（唤醒）
         → 若其优先级 > 当前任务 → 请求切换（xSwitchRequired = pdTRUE）
```

"唤醒"本身是**必然**发生的（只要有人等着且队有空间）——它只是把任务从"阻塞列表"搬到"就绪列表"（[[任务调度]]）。**是否切换**是下一步的独立判断。

## 场景 A：任务上下文发送（`xQueueSend`）→ 立即切换

在任务里调用 `xQueueSend`，唤醒更高优先级任务时：

```
任务 A 调 xQueueSend
   → 唤醒任务 B（优先级更高）
   → xSwitchRequired = pdTRUE
   → xQueueSend 返回前（临界区外）触发 PendSV
   → 返回后 PendSV 立即执行：保存 A → 恢复 B → 运行 B
```

**会立即切换**——但前提是**唤醒的任务优先级确实更高**。若唤醒的是同/低优先级任务，只入就绪列表，**不切换**（等时间片轮转或 A 自己阻塞）。

## 场景 B：ISR 中发送（`xQueueSendFromISR`）→ 不立即，退出中断才切

在中断里发送队列，唤醒更高优先级任务时：

```
ISR 调 xQueueSendToBackFromISR
   → 唤醒任务 B（优先级更高）
   → 只置 *pxHigherPriorityTaskWoken = pdTRUE（记住"需要切换"）
   → ISR 继续执行，不切换！
   → ISR 返回时：portYIELD_FROM_ISR(pxHigherPriorityTaskWoken)
        └─ 触发 PendSV → 等所有高优先级中断处理完 → 切换
```

**关键区别**：ISR **不会在中断内立即切换**，只是通过 `pxHigherPriorityTaskWoken` 标志"记账"，由**退出中断时的 `portYIELD_FROM_ISR`** 触发 PendSV，在中断处理结束后才真正切换。

## 为什么 ISR 不能立即切换？（PendSV 设计）

这正是 [[任务上下文切换]] 强调的：

> PendSV 是**可被其他中断抢占的异常**，把切换推迟到所有高优先级中断处理完之后执行，避免在中断上下文里做重操作、保证实时性。

- **ISR 里做切换不安全**：会破坏正在处理的中断现场、被更高优先级中断打断导致上下文不一致；
- **所以 FreeRTOS 用"标志 + 退出时 PendSV"**：ISR 只置位，真正切换交给 PendSV 在最合适的时机（所有高优中断结束后）完成。

## 对比总结

| 维度 | 任务上下文 `xQueueSend` | ISR 上下文 `xQueueSendFromISR` |
| --- | --- | --- |
| 唤醒等待者 | ✅ 必然（若有） | ✅ 必然（若有） |
| 切换请求 | 内部置 `xSwitchRequired` | 置 `*pxHigherPriorityTaskWoken` |
| **立即切换？** | **是**（返回前触发 PendSV） | **否**（等退出中断时 `portYIELD_FROM_ISR`） |
| 真正切换时机 | API 返回后，PendSV 立即 | 所有高优先级中断处理完后，PendSV |
| 前提 | 唤醒任务优先级**必须更高** | 同左 |

## 一句话记忆

> **发送队列只负责"唤醒"（入就绪列表）；"立即切不切"看两件事——优先级够不够高（必须更高）、在哪发的（任务里发→立即 PendSV 切；中断里发→只记标志，退出中断才切）。** ISR 从不直接切换，一切交给 PendSV 收尾。
