# 回调函数是并行还是并发？

## 核心结论

**回调函数本身属于并发机制，不是并行**——但它可以与并行的硬件配合。要分两层看：**回调的"触发源"可能是并行的，而回调的"执行"永远是并发的**。

| 层次 | 例子 | 归属 |
| --- | --- | --- |
| 触发源 | DMA 独立搬运数据（与 CPU 同时干活） | **并行** |
| 执行者 | ISR 在 CPU 上抢占/打断任务运行 | **并发** |

## 回调函数的本质

回调函数（Callback）是一种"你帮我干活，干完叫我"的机制：代码事先注册一段函数，事件发生时由系统调用它。在嵌入式/事件驱动场景中，最常见的形态就是**中断服务函数（ISR）**。

典型实例：[[DMA双缓冲]] 的时序图中，DMA 搬运完成后触发中断，**ISR（回调）更新信号量 → 唤醒调度 task**。这里的 ISR 就是硬件事件触发的回调。

## 为什么回调是并发的

按照 [[并发与并行]] 的定义——并发是"逻辑上的同时（交替推进）"，本质是任务如何组织、调度、同步，**单核即可满足**：

- 中断回调触发时，CPU 会**暂停当前正在执行的任务**，跳去运行 ISR，执行完再回到原任务；
- 单核 CPU 同一时刻只能执行一条指令，ISR 与主任务只是**交错推进**，从外部看"好像同时在跑"；
- 这正是 [[并发与并行]] 中"一人来回切换烧三壶水"的模型——回调不创建任何新的执行单元，它只是让 CPU 在代码段之间切换。

所以**回调描述的是一种"执行组织方式"，属于并发范畴**。

## 与并行的关系：触发源可以并行

回调并不排斥并行，关键看**触发它的事件来自哪里**。以 [[DMA双缓冲]] 为例：DMA 填 B 的同时 CPU 处理 A，这是**硬件并行**（DMA 是独立 Master）；而当 DMA 填完触发中断，ISR 回到 CPU 上抢占执行，这段回调代码本身是**并发**的。底层确实是"[[并发与并行]] 的叠加"——并行发生在硬件单元之间，并发发生在 CPU 的任务调度内部。

## 结论

> 回调函数（尤其是中断回调）是**并发**的具体实现手段——它依赖 CPU 的任务抢占与交错推进，不产生新的并行执行单元。但回调可以**响应并行的硬件事件**（如 DMA、多核），从而让"并发执行的回调"与"并行工作的硬件"协同，构成高效系统。
