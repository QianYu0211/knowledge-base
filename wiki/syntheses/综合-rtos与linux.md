# 综合：RTOS 与 Linux 的区别

**一句话总览**：**RTOS（如 [[FreeRTOS]]）为"确定性"而生——牺牲功能换取可预测的响应时间；Linux 为"通用性"而生——牺牲实时性换取丰富的功能与生态。** 本质是**硬实时操作系统 vs 通用操作系统（GPOS）**的区别，从调度、内存、任务模型到资源需求，几乎每个层面都不同。

> 本页 **RTOS 侧以知识库 [[FreeRTOS]] 体系为权威**（调度/内存/IPC 均有库内页面支撑），**Linux 侧为通用知识补充**（库内暂无 Linux 专项页）。

## 核心对比表

| 维度 | RTOS（[[FreeRTOS]]） | Linux |
| --- | --- | --- |
| **实时性** | **硬实时**：deadline 可保证，响应时间可预测（微秒级） | **软实时**：尽力而为，普通内核不保证 deadline（PREEMPT_RT 补丁才接近硬实时） |
| **调度器** | 固定优先级**抢占式** + 时间片轮转，优先级数量少、行为确定（[[任务调度]]） | **CFS 完全公平调度**（虚拟运行时间，红黑树）+ `SCHED_FIFO`/`RR` 实时策略 |
| **内存管理** | **无 MMU**：静态数组 `ucHeap`、任务栈/TCB 从堆分配、无虚拟内存（[[综合-freertos任务内存分配]]） | **MMU + 虚拟内存**：进程隔离、按需调页、`malloc` 动态分配 |
| **任务/进程模型** | **任务共享地址空间**，切换轻量（寄存器进出，[[任务上下文切换]]） | **进程独立地址空间**，切换重量级（内核态切换 + TLB 刷新） |
| **IPC** | 简单且确定：[[信号量]] / [[消息队列]] / 互斥锁 | 丰富但开销大：管道 / 信号 / 共享内存 / socket / 消息队列 |
| **优先级反转** | 经典问题，用优先级继承解决（FreeRTOS 互斥锁） | 内核同样处理（RT 互斥锁），但更复杂 |
| **资源占用** | **KB 级** RAM/Flash | **MB 级** 起步 |
| **硬件要求** | MCU（Cortex-M，无 MMU） | MPU/SoC（需 MMU，如 Cortex-A） |
| **启动** | 毫秒级（main → 初始化 → 调度器） | 秒级（bootloader → kernel → init → 用户态） |
| **开发复杂度** | 简单直接，驱动直接操作寄存器 | 完整驱动框架（设备树/内核模块），生态庞大 |

## 四个本质差异

**1. 调度的哲学：确定性 vs 公平性**
RTOS 用**固定优先级抢占**——最高优先级就绪任务立刻运行，行为可预测，这是硬实时的根基（[[综合-优先级规划]] 的 deadline 驱动）。Linux 的 **CFS** 追求"公平"——让所有进程按权重共享 CPU，公平性优先于确定性；要实时得显式用 `SCHED_FIFO` 并承担复杂性。

**2. 内存模型：共享 vs 隔离**
FreeRTOS 任务**共享同一地址空间**，切换只换寄存器（轻量），但也意味着一个任务越界会破坏整个系统。Linux 进程**靠 MMU 隔离**，一个进程崩溃不影响其他进程（健壮），但切换要刷 TLB（重量级）。

**3. 硬件地基：MCU vs MPU**
RTOS 跑在无 MMU 的 MCU（[[STM32]]）上，资源以 KB 计；Linux 需要带 MMU 的 MPU/SoC，资源以 MB 计。这是选型的第一约束。

**4. 实时性的保证层级**
RTOS 的确定性来自**内核本身**（抢占式 + 短临界区）；Linux 的实时性需要补丁（PREEMPT_RT）或实时核（如 Xenomai），且仍有页错误、调度延迟等不确定性来源。

## 选型决策

| 场景 | 选谁 |
| --- | --- |
| 硬实时控制（电机、采样，deadline 毫秒/微秒级） | **RTOS**（[[综合-优先级规划]] deadline 驱动） |
| 资源受限 MCU（Flash/RAM KB 级） | **RTOS** |
| 需要丰富生态（网络协议栈、文件系统、GUI、AI） | **Linux** |
| 需要进程隔离、崩溃不拖垮系统 | **Linux** |
| 复杂业务 + 部分实时需求 | **Linux + PREEMPT_RT / 双核分工**（MCU 做实时 + MPU 跑 Linux） |

## 一句话记忆

> **RTOS 用功能换确定性，Linux 用确定性换功能**——要"算得准"选 RTOS，要"跑得多"选 Linux；复杂系统常两者分工：MCU 扛实时、MPU 跑应用。
