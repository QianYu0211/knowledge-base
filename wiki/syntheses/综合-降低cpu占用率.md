# 综合：降低 CPU 占用率的五级阶梯

**一句话总览**：降低 CPU 占用率有两条主线——**"让 CPU 少干活"**（硬件卸载、中断精简、攒批处理）与**"让 CPU 睡觉"**（阻塞让权、低功耗睡眠）。知识库给出的完整路径是一条五级阶梯：**卸载 → 精简 → 攒批 → 让权 → 睡觉**，从"CPU 少干活"推进到"CPU 不干活"。[[综合-adc高效采集]] 给出了这条路径的浓缩版原则：

> CPU 只负责发起，转换交给 ADC、搬运交给 DMA，CPU 在整个任务结束后才被占用一次。

## 总览：五级阶梯

| 级别 | 手段 | 作用对象 | CPU 介入程度 | 代表页面 |
| --- | --- | --- | --- | --- |
| ① 卸载 | 外设硬件替 CPU 干活 | 数据搬运/转换 | 全程只占一次 | [[DMA]] / [[综合-adc高效采集]] |
| ② 精简 | 把 ISR 做到最短 | 中断处理 | 中断时间最小化 | [[中断优化]] / [[中断上半部与下半部]] |
| ③ 攒批 | 缓冲降低事件频率 | 中断/事件频次 | 被打断次数下降 | [[环形缓冲区]] / [[DMA双缓冲]] |
| ④ 让权 | 阻塞代替忙轮询 | 任务等待 | 空转 → 0 | [[消息队列]] / [[信号量]] / [[任务调度]] |
| ⑤ 睡觉 | 空闲时睡眠 | 整机功耗 | 占用率归零后去掉空转 | [[低功耗模式]] / [[WFI与WFE]] |

> 阶梯的推进逻辑：①~③ 是**减少"每次干活的量"**，④ 是**消除"没活干还占着 CPU"**，⑤ 是**让"无事可做的 CPU"停止空耗**。前四步降占用率，第五步把降下来的"空闲"转化为节能。

## 第一级：硬件卸载——让外设替 CPU 干活

[[DMA]] 是总线上的独立 Master，能独立于 CPU 搬运数据。[[综合-adc高效采集]] 给出取数方式的三境界：

1. **轮询等待**——CPU 被转换过程占用，原地等待，**效率最低**；
2. **转换完成中断**——CPU 每次转换完成后被短暂占用；
3. **ADC + DMA**——ADC 转完数据，DMA 自动搬进内存，搬运完成才发一次中断，**CPU 全程只被占用一次**。

再配 [[DMA双缓冲]]（两块内存 A/B 乒乓 + 双 [[信号量]]），DMA 填 B 时 CPU 处理 A，形成"生产-消费流水线"，**谁也不用等谁**——底层是 DMA 与 CPU 在硬件上真正并行（[[并发与并行]]）。

**适用场景**：ADC 采集、串口接收、SPI/Flash 搬运、OTA 下载等一切"数据搬移"密集场景。原则：**凡是可以由外设完成的重复性搬移，都不要让 CPU 逐字节做**。

## 第二级：中断精简——把 ISR 做到最短

[[中断优化]] 用"急诊室"比喻统领：CPU 是唯一值班医生，ISR 只做"初步诊断"，重活留给任务。ISR 运行于中断上下文，会阻塞同/低优先级中断、抢占所有任务——**ISR 越长，系统实时性越差**（[[中断上半部与下半部]]）。

三面优化：

- **精简上半部**：ISR 去除函数调用/复杂分支/循环/浮点/printf，只做三类"必要操作"——**时间敏感**（如立刻读 `ADC1->DR`）、**硬件敏感**（如重配 DMA 通道）、**不可重入**（原子标志更新）；
- **优化下半部**：中断线程化用 [[消息队列]]（`xQueueSendToBackFromISR()`）唤醒任务，任务 `xQueueReceive()` 处理；
- **先量化再优化**：GPIO 翻转 / ETM Trace / 软件日志（时间戳入 [[环形缓冲区]]）三种手段跟踪 ISR 耗时与丢中断，**没有数据不动手**。

同时警惕 [[中断优化]] 列出的**丢中断四情况**：连清标志位、悬起脉冲、未清标志位、总线仲裁冲突（DMA 占 AHB 导致 CAN FIFO 溢出）。

**适用场景**：一切中断驱动的 I/O。原则：**ISR 只做"推迟就丢"的事，其余全部推迟到任务**。

## 第三级：缓冲攒批——把"一次一字节"变成"一批一处理"

事件频率越高，CPU 被抢占次数越多。[[环形缓冲区]] 用读/写指针回绕缓存多帧，**攒批处理、容忍消费端偶发缓慢**（[[综合-生产消费缓冲]]）；配合 DMA 半满中断（隐式双缓冲），中断频率从"每字节一次"降到"每半缓冲一次"。

**原理**：把"生产（硬件/中断）与消费（CPU/任务）"用一块暂存区解耦——生产方只管写入，消费方攒够一批再处理。四种形态（双缓冲/环形/队列/对象池）的选型见 [[综合-生产消费缓冲]]。

**适用场景**：串口不定长接收、中断日志、遥测数据聚合。原则：**能攒批就别逐项打断 CPU**。

## 第四级：阻塞让权——把 CPU 让出去

这是 RTOS 场景最关键的一级。[[消息队列]] / [[信号量]] 提供**阻塞语义**：空队消费阻塞、满队生产阻塞，阻塞的任务**不占 CPU**，调度器把时间片交给其他就绪任务或空闲任务（[[任务调度]]）。

| 等待方式 | CPU 占用 | 说明 |
| --- | --- | --- |
| **忙轮询**（`while(!flag);`） | **100% 空转** | CPU 被无谓消耗，浪费电量与算力 |
| **阻塞等待**（队列/信号量） | **0%** | 任务挂起，调度器让出 CPU |

**附带权衡**：[[任务上下文切换]] 指出"任务不宜过碎"——频繁切换本身消耗 CPU（寄存器搬进搬出 + 流水线刷新）。任务粒度要平衡"响应性"与"切换开销"。

**适用场景**：一切"等事件/等数据/等资源"的等待。原则：**RTOS 下永远用阻塞，不用忙轮询**。

## 第五级：低功耗睡眠——把"空转"也去掉

当占用率已经降到 0、CPU 无事可做时，用 [[低功耗模式]] 让它真正睡过去。[[WFI与WFE]] 是 Cortex-M 的软件入口：`WFI`（等中断）执行后 CPU 挂起直到任意中断唤醒；`WFE`（等事件）等特定外设事件，避免被无关中断反复唤醒。

STM32 三档睡眠（[[低功耗模式]]）：

| 模式 | CPU 内核 | SRAM/寄存器 | 唤醒代价 |
| --- | --- | --- | --- |
| 睡眠 Sleep | 停时钟，醒来即续跑 | 保留 | 最低（无状态丢失） |
| 停机 Stop | 关闭 | 保留 | 中（唤醒后需重配时钟） |
| 待机 Standby | 断电 | **丢失** | 最高（等同复位） |

> **严格说低功耗降的是"功耗"而非"占用率"，但两者是同一目标的两步**：先让 CPU 无活可干（占用率→0），再让它停止空转（功耗→最低）。典型做法是把 `WFI` 挂到 RTOS **空闲任务钩子**里——调度器发现没有就绪任务时自动睡眠，任意中断唤醒后回到调度器。实现要点：进出低功耗前后用 `HAL_SuspendTick()`/`HAL_ResumeTick()` 挂起/恢复 SysTick，避免唤醒后节拍错乱（[[低功耗模式]]）。

## 补充：编译与算法侧

- **编译优化**：[[编译优化]] 的 as-if 法则（寄存器缓存/指令重排/死代码消除）可在编译层减少指令数——注意它不影响语义，但可能与 [[volatile]] 正确性约束冲突；
- **算法选型**：占用率也取决于算法效率——如 [[滤波算法]] 里查表/递推实现比朴素实现省 CPU；[[对象池]] 预分配复用比频繁 malloc/free 快 10~100 倍。

## 实践提示：先量化，再优化

[[中断优化]] 的第一原则是**先跟踪后优化**（GPIO 翻转 / ETM / 软件日志）。同理，降占用率的第一步永远是先搞清楚 CPU 时间花在哪：是忙轮询空转？ISR 过长？还是频繁中断被打断？没有 profile 数据就动手优化，容易优化错地方。

**一句话记忆**：卸载（DMA）→ 精简（中断）→ 攒批（缓冲）→ 让权（阻塞）→ 睡觉（WFI），从"CPU 少干活"推进到"CPU 不干活"。
