📋 场景2：回顾 - 结构体就是对象的"设计图纸"

单个LED对象的定义

LED对象结构

📍 端口号 (port)
📍 引脚号 (pin)
📍 状态 (state)
// 定义LED对象的结构体（设计图纸） typedef struct { uint8_t port; // 端口号：比如GPIOA uint8_t pin; // 引脚号：比如pin3 uint8_t state; // 状态：0=关闭，1=打开 } LED_t; // 创建一个LED对象实例 LED_t led1 = {1, 3, 0}; // 端口1，引脚3，初始关闭
🎯 关键概念：结构体（struct）就像是建筑设计图纸，定义了对象应该有哪些属性。根据图纸，我们可以"建造"出一个个具体的对象实例。

⚖️ 场景3：对比 - 为什么需要数组？

❌ 方法1：定义10个单独变量
LED_t led0 = {1, 0, 0}; LED_t led1 = {1, 1, 0}; LED_t led2 = {1, 2, 0}; LED_t led3 = {1, 3, 0}; LED_t led4 = {1, 4, 0}; // ... 还有5个
问题：
• 代码重复，冗长
• 无法用循环批量操作
• 维护困难
✅ 方法2：使用对象数组
// 一次性定义10个LED对象 LED_t leds[10] = { {1, 0, 0}, {1, 1, 0}, {1, 2, 0}, // ... };
优势：
• 代码简洁
• 可以用循环批量操作
• 易于维护和扩展

🔧 场景4：对象数组的声明与初始化

// 语法格式：类型名 数组名[元素个数] = {初始化列表}; LED_t leds[4] = { {1, 0, 0}, // leds[0]：端口1，引脚0，关闭 {1, 1, 0}, // leds[1]：端口1，引脚1，关闭 {1, 2, 1}, // leds[2]：端口1，引脚2，打开 {1, 3, 0} // leds[3]：端口1，引脚3，关闭 };

内存布局可视化

0x1000 leds[0] → {port:1, pin:0, state:0}
0x1003 leds[1] → {port:1, pin:1, state:0}
0x1006 leds[2] → {port:1, pin:2, state:1}
0x1009 leds[3] → {port:1, pin:3, state:0}
🎯 重点：数组中的每个元素都是一个完整的对象，在内存中连续存储。每个对象占用3个字节（假设每个uint8_t占1字节）。

🎮 场景5：访问与操作对象数组

// 1. 通过下标访问单个对象 leds[2].state = 1; // 打开第3个LED（下标从0开始） uint8_t pin = leds[1].pin; // 读取第2个LED的引脚号 // 2. 使用循环遍历所有对象 for(int i = 0; i < 4; i++) { leds[i].state = 1; // 打开所有LED } // 3. 批量修改 for(int i = 0; i < 4; i++) { if(i % 2 == 0) { leds[i].state = 1; // 打开偶数位置的LED } }

💼 场景6：实战案例 - GPIO端口管理

// GPIO引脚配置结构体 typedef struct { uint8_t port; // 端口号：A=0, B=1, C=2... uint8_t pin; // 引脚号：0-15 uint8_t mode; // 模式：0=输入，1=输出 uint8_t state; // 状态：0=低，1=高 } GPIO_Pin_t; // 定义8个GPIO引脚的配置数组 GPIO_Pin_t gpio_pins[8] = { {0, 0, 1, 0}, // PA0: 输出模式，初始低电平 {0, 1, 1, 0}, // PA1: 输出模式，初始低电平 {0, 2, 1, 0}, // PA2: 输出模式，初始低电平 {0, 3, 0, 0}, // PA3: 输入模式 {1, 0, 1, 0}, // PB0: 输出模式，初始低电平 {1, 1, 1, 0}, // PB1: 输出模式，初始低电平 {1, 2, 0, 0}, // PB2: 输入模式 {1, 3, 1, 1} // PB3: 输出模式，初始高电平 }; // 批量初始化GPIO引脚 void GPIO_Init_All(void) { for(int i = 0; i < 8; i++) { // 根据配置初始化每个引脚 GPIO_Init(gpio_pins[i].port, gpio_pins[i].pin, gpio_pins[i].mode); // 设置初始状态 if(gpio_pins[i].mode == 1) { // 如果是输出模式 GPIO_Write(gpio_pins[i].port, gpio_pins[i].pin, gpio_pins[i].state); } } } // 控制指定LED void LED_Control(uint8_t index, uint8_t state) { if(index < 8 && gpio_pins[index].mode == 1) { gpio_pins[index].state = state; GPIO_Write(gpio_pins[index].port, gpio_pins[index].pin, state); } }
💡 实际应用：在嵌入式系统中，我们经常需要管理多个GPIO引脚。使用对象数组可以让配置更清晰，初始化更方便，代码更易维护。

📚 场景7：总结与对比

静态对象数组的特点

✅ 优点

  • 内存固定：编译时就分配好内存
  • 访问快速：无需动态分配，效率高
  • 使用简单：不需要手动释放内存
  • 代码清晰：一次性定义所有对象
  • 批量操作：可用循环统一处理

⚠️ 限制

  • 大小固定：数组大小必须在编译时确定
  • 不可扩展：运行时无法增加或减少元素
  • 内存占用：即使不用也占用内存
  • 栈空间限制：大数组可能导致栈溢出

🎯 适用场景

• 对象数量固定：如8个GPIO引脚、4个LED灯
• 嵌入式系统：资源有限，需要确定性的内存分配
• 配置表：传感器配置、通信端口配置等
• 小型数组：元素较少（一般少于100个）
