# CRC（循环冗余校验）

#### 一、CRC是什么？

**CRC** 是一种功能强大且在工程中广泛应用的**差错检测算法**。它的核心使命是确保数据在传输或存储过程中没有发生意外的改变（例如，由于噪声干扰、位翻转等）。

**核心比喻：**

CRC就像是为数据（例如一串二进制代码）计算一个**“数学指纹”**。

- **发送方**：计算出原始数据的“指纹”（CRC校验码），然后把 **\[原始数据 \+ 指纹\]** 一起发送出去。

- **接收方**：收到数据后，用**完全相同的方法**为接收到的数据部分计算一个新的“指纹”。

- **校验**：比较自己计算出的新指纹和接收到的旧指纹。

    - 如果两者**完全一致**，就高度确信数据在传输过程中是完好无损的。

    - 如果**不一致**，就说明数据已损坏，需要请求重传

CRC之所以“高明”，是因为它基于**多项式除法**，检错能力远超简单的**累加和**或**异或和**。

#### 二、模2多项式除法

这部分是CRC最核心、最抽象的原理。

1. **数据即多项式**: 在CRC的世界里，任何一串二进制数据都被看作是一个**多项式**。例如，数据`1101` \(二进制\) 就代表多项式 `1x³ + 1x² + 0x¹ + 1x⁰`  =\>  `x³ + x² + 1`。

2. **“除数” \- 生成多项式**:

    1. 通信双方必须**预先约定**一个固定不变的“除数”，这就是**生成多项式**，例如 `x⁸ + x⁵ + x⁴ + x¹ + 1`。

    2. 这个多项式的选择直接决定了CRC算法的检错能力，是CRC标准的核心。**CRC\-8, CRC\-16, CRC\-32**，其根本区别就在于使用了不同阶数和形式的生成多项式。

    3. 在工程中，我们通常用一个十六进制数来表示它，例如，`x⁸ + x⁵ + x⁴ + x¹ + 1` 就表示为 **`0x131`**（省略最高位的`1`后为**`0x31`**）

3. **计算过程 \- 模2除法**:

CRC的计算过程，本质上就是一次**“带余数的除法”**，是在一个特殊的数学领域（伽罗瓦域GF\(2\)）中进行的。

- **被除数**: 原始数据后面**补上N个0**（N是生成多项式的阶数，例如CRC\-8就补8个0）。

- **除法规则**: 这种除法非常简单，它使用的是**模2运算**，即：

    - **加法不进位 \-\> 等同于异或\(XOR\)**

    - **减法不借位 \-\> 也等同于异或\(XOR\)**

- **CRC校验码**: 最终计算出的**余数**，就是CRC校验码

**这个过程就像做一道长除法题，但把所有的减法都换成了异或。**

#### 三、 从数学到代码

##### 1\. 核心部件：线性反馈移位寄存器 \(LFSR\)

CRC的计算过程可以用一个硬件电路——**LFSR**——来实现。这是一种由移位寄存器和异或门构成的电路，它能以极高的速度、逐比特地完成模2除法。**软件实现CRC，本质上就是在用代码去“模拟”这个硬件的行为。**

LFSR（线性反馈移位寄存器）是一种基于移位寄存器和反馈函数的数字电路。CRC本质上是一种LFSR。

工作原理：

- 寄存器存储当前状态（n位）

- 反馈函数决定哪些位参与XOR

- 每次时钟脉冲，寄存器右移一位

- 最低位输出，同时反馈值移入最高位

##### 2\. 软件实现方法

- **方法一：直接计算法 / 位计算法 \(Bit\-wise\)**

    - **原理**: 完全模拟LFSR的行为。通过循环，一个比特一个比特地处理数据。

    - **优点**: 代码直观，容易理解其工作原理，ROM占用小。

    - **缺点**: **效率极低**，因为CPU不擅长处理单个比特。

    - **代码特征**: 通常包含两层循环，外层循环处理每个字节，内层循环处理字节内的8个比特

- **方法二：查表法 \(Table\-Driven\)**

    - **原理**: 这是对直接计算法的一种**极致优化**。预先计算出 **所有可能的8位输入（0\-255）**对应的CRC结果，并将它们存储在一个**256项的查找表**中。

    - **计算过程**: 在处理每个字节时，不再需要8次循环，而是通过一次异或和一次查表操作，直接得到结果。

    - **优点**: **效率极高**，速度是直接计算法的数十倍甚至更高。

    - **缺点**: 需要额外的 **256字节（CRC\-8）或512字节（CRC\-16）的ROM/Flash** 空间来存储查找表。

    - **代码特征**: 只有一个处理字节的外层循环，循环体内核心操作是 `crc = crc_table[index]`

    CRC\-16查表法实现：

    ```
    #define CRC16_TABLE_SIZE 256
    static uint16_t crc16_table[CRC16_TABLE_SIZE];
    
    void crc16_init(void) {
        for (int i = 0; i < 256; i++) {
            uint16_t crc = i;
            for (int j = 0; j < 8; j++) {
                if (crc & 0x0001) {
                    crc = (crc >> 1) ^ 0xA001;
                } else {
                    crc >>= 1;
                }
            }
            crc16_table[i] = crc;
        }
    }
    
    uint16_t crc16_calc(const uint8_t* data, size_t len) {
        uint16_t crc = 0xFFFF;
        while (len--) {
            uint8_t idx = (crc ^ *data) & 0xFF;
            crc = (crc >> 8) ^ crc16_table[idx];
            data++;
        }
        return crc;
    }
    ```

    CRC\-32查表法实现：

    ```
    #define CRC32_TABLE_SIZE 256
    static uint32_t crc32_table[CRC32_TABLE_SIZE];
    
    void crc32_init(void) {
        for (int i = 0; i < 256; i++) {
            uint32_t crc = i;
            for (int j = 0; j < 8; j++) {
                if (crc & 1) {
                    crc = (crc >> 1) ^ 0xEDB88320;
                } else {
                    crc >>= 1;
                }
            }
            crc32_table[i] = crc;
        }
    }
    
    uint32_t crc32_calc(const uint8_t* data, size_t len) {
        uint32_t crc = 0xFFFFFFFF;
        while (len--) {
            uint8_t idx = (crc ^ *data) & 0xFF;
            crc = (crc >> 8) ^ crc32_table[idx];
            data++;
        }
        return crc ^ 0xFFFFFFFF;
    }
    ```

#### 四、 “标准”CRC的完整定义

一个CRC算法并不仅仅由它的多项式决定。为了让不同系统间的CRC计算结果完全一致，一个完整的CRC标准必须定义以下**所有参数**：

1. **多项式**: 算法核心，例如`0x1021` \(CRC\-16\-CCITT\)。

2. **宽度**: 校验码的位数（8, 16, 32\.\.\.）。

3. **初始值**: 计算开始前寄存器的预设值，例如`0x0000`或`0xFFFF`。非零初始值可以检测出数据**前导零**的错误。

4. **输入数据反转**: 计算前，是否要将每个输入字节的比特顺序颠倒。

5. **输出结果反转**: 计算后，是否要将最终的CRC值的比特顺序颠倒。

6. **最终异或值**: 返回结果前，是否要将CRC值与一个固定的掩码进行异或。

**实践中的关键**: 在进行通信时，**发送方和接收方必须确保以上所有6个参数完全一致**，否则校验必然失败。

#### 五、 CRC的检错能力与局限

- **强大之处**:

    - 能100%检测出所有**奇数个**比特的错误。

    - 能100%检测出所有**长度小于等于多项式阶数**的**突发错误**（连续的比特错误）。

    - 能以极高的概率（接近100%）检测出其他突发错误和随机错误

- **局限之处**:

    - CRC**只能检错，不能纠错**。

    - CRC**不是加密算法**。它不提供任何保密性，并且对于恶意攻击者来说，很容易在篡改数据的同时，也计算出一个新的、匹配的CRC值。
